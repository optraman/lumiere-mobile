# Люмьер — мобильная версия (этап 1: каталог)

Первый этап мобильного приложения — портирование каталога TMDB из Android TV приложения брата
(`ui/home/HomeScreen.kt`, `data/tmdb/*`) на React Native / Expo. Экран "Смотреть" пока заглушка —
подключение HDRezka (с её antibot-защитой Anubis) и плеера будет следующим этапом.

**Важно:** этот проект написан в облачной песочнице, где доступ к npm-реестру заблокирован
политикой безопасности — поэтому `npm install` здесь ни разу не запускался и код не был
собран/протестирован живьём. Первым делом после переноса на свой компьютер стоит прогнать шаги
ниже и прислать мне, если что-то не собирается — это нормально для первого прохода.

## Запуск (на своём компьютере, не в этой сессии)

Проект на **Expo SDK 57**.

1. Установка зависимостей:
   ```
   npm.cmd install
   ```

2. Ключ TMDB: themoviedb.org → аватар → Настройки → API → "Ключ API (v3 auth)".
   Впишите его в файл `.env` в корне проекта:
   ```
   EXPO_PUBLIC_TMDB_API_KEY=ваш_ключ
   ```

3. Запуск:
   ```
   npx.cmd expo start --clear
   ```
   В терминале появится QR-код. Отсканируйте его камерой iPhone.
   Если телефон в другой сети — `npx.cmd expo start --tunnel --clear`.

   `.cmd` в командах — из-за политики выполнения скриптов PowerShell в Windows. Если выполнить
   `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, можно писать просто `npm` и `npx`.

## Источник видео

Онлайн берётся из **Collaps** (`src/api/collaps/`). Протокол списан с открытого исходника Lampac
(`Modules/OnlineRUS/Collaps`):

```
GET https://api.luxembd.ws/embed/imdb/{tt…}     заголовок Origin: https://kinokrad.my
```

Токена и входа не требуется — тайтл открывается по номеру IMDB, который берётся у TMDB. Ответ —
страница, внутри которой либо `makePlayer({…})` у фильма, либо `seasons: […]` у сериала; во втором
случае это **весь сериал одним запросом**: сезоны, серии, прямые ссылки HLS, субтитры и названия
звуковых дорожек. Качества лежат внутри master-плейлиста и выбираются плеером автоматически,
озвучки — звуковыми дорожками внутри того же файла.

Проверки:

```
node tools/collaps-check.js          разбор формата, без сети (гоняет настоящий src/api/collaps)
node tools/collaps-probe.js "…"      полная цепочка вживую: TMDB → страница → HEAD по файлу
```

Адреса и Origin вынесены константами в `src/api/collaps/net.ts` — у Lampac они время от времени
меняются, и менять их надо там.

## Что перенесено из ТВ-версии

Это порт, а не приложение «по мотивам» — состав ленты, фильтры и оформление взяты из кода брата,
а не придуманы заново.

| Что | Откуда (ТВ) | Куда (мобильное) |
|-----|-------------|------------------|
| Модели данных | `data/model/Media.kt` | `src/types/media.ts` |
| Клиент TMDB | `data/tmdb/TmdbApi.kt` | `src/api/tmdb.ts` |
| DTO → модель | `data/tmdb/TmdbMapper.kt` | `src/api/mapper.ts` |
| Состав и порядок рядов | `TmdbRepository.homeFeed/moviesFeed/tvFeed` | `src/api/feed.ts` |
| Фильтры ленты (`curated`, `mainstream`, языки, CJK) | `TmdbRepository` + `TmdbMapper` | `src/api/curate.ts` |
| Ряд по времени суток | `TmdbRepository.liveRowSpec()` | `src/api/liveRow.ts` |
| Палитра | `ui/theme/Theme.kt` | `src/theme/colors.ts` |
| Шрифты Bounded + Manrope | `res/font/*` | `assets/fonts/*`, `src/theme/fonts.ts` |
| Герой, Топ-10, баннеры | `ui/components/Billboard.kt`, `Cards.kt` | `src/components/*` |
| Нижняя панель вкладок | `ui/home/TopNav.kt` | `app/(tabs)/_layout.tsx` |
| Кнопки | `ui/components/AppButton.kt` | `src/components/AppButton.tsx` |
| Токены анимации | `ui/theme/Motion.kt` | `src/theme/motion.ts` |

Важные решения оригинала, которые НЕ надо «чинить»:

- **Палитра монохромная**, почти чёрная, без цветного акцента. Единственный акцент — тёплый
  пергамент `#CCCC99` («акцентный цвет для всего приложения — cccc99»). Выделение показывается им и
  тёплым почти-белым подчёркиванием, а не синим/красным «как принято».
- **Два шрифта, каждый на своём месте:** Bounded только для крупных заголовков, Manrope — весь
  остальной интерфейс. Это результат отдельного перебора шрифтов владельцем.
- **Фильтры ленты жёсткие и намеренные:** отбрасываются ток-шоу/новости/реалити (по id жанра),
  тайтлы с меньше чем 200 оценками, индийское/филиппинское и испанское/французское/итальянское/
  немецкое кино безусловно, азиатское неевропейское — кроме культового (8.2+). Поиск через эти
  фильтры НЕ проходит: если человек ищет что-то редкое, он этого хочет.
- **«Сейчас в кино» стоит последним** широким рядом — это намеренная награда внизу ленты, а не
  конкурент герою вверху.
- **В «Фильмах» «Популярное» идёт перед «Топ 10»** — правка самого владельца.

### Дизайн-код (перенесён)

- **Токены анимации** (`ui/theme/Motion.kt` → `src/theme/motion.ts`): три длительности (120 / 240 /
  400 мс) и одна кривая `cubic-bezier(0.2, 0, 0, 1)` на всё. Не заводить новых значений «по случаю» —
  до появления этих токенов в приложении было десять разных длительностей и три кривые, и глаз
  читал это как интерфейс из несвязанных кусков.
- **Плашка рейтинга** (`Cards.kt` → `src/components/RatingChip.tsx`): УГЛЫ ОСТРЫЕ, скругления быть
  не должно («рейтинг в карточках — без скругления углов, тоже с острыми углами»). Пороги цветов:
  зелёный `#46C755` от 7.0, янтарный `#D69A34` от 5.5, серый `#6B6B76` ниже. Шрифт — Bounded,
  «как в хиро». Отступы растут вместе с кеглем.
- **Знак «Люмьера»** (`res/drawable/logo_mark.xml` → `src/components/Logo.tsx`): рамка киноплёнки +
  треугольник-луч, перенесён путь в путь.
- **Иконки нижней панели** (`ui/home/TopNav.kt` → `app/(tabs)/_layout.tsx`): у Влада это
  СТАНДАРТНЫЙ набор Material Icons Filled, а не рисованные глифы — `Icons.Filled.Home` / `.Movie` /
  `.LiveTv` / `.Search`. Здесь взяты те же самые: `home`, `movie`, `live-tv`, `search`. Не менять на
  «более симпатичный» набор.
- **Поведение панели** (`TopNav.kt`): капсулы/подложки под выделением НЕТ намеренно — «the focus cue
  is motion and brightness». Активная вкладка — `ColorOnBg` целиком, неактивная — ТОТ ЖЕ цвет на 50%
  прозрачности (`colors.onBgDim`), а не отдельный серый. Пергаментный `ColorFocusFill` в панели не
  участвует: в оригинале он заливает только круглый бейдж настроек и элемент в фокусе.
- **Кнопки** (`ui/components/AppButton.kt` → `src/components/AppButton.tsx`): «одна кнопка везде» —
  пилюля радиусом 30, подпись titleMedium, три варианта (Primary / Tonal / Ghost). В нажатом
  состоянии кнопка становится сплошной белой с ЧЁРНЫМ текстом — это правило контраста появилось
  потому, что стандартные tv-material кнопки превращались в белое-на-белом и исчезали.

- **Нижняя панель — жидкое стекло в духе iOS 26** (`src/components/GlassTabBar.tsx`). Это НЕ порт, а
  решение для телефона: у Влада панель наверху и непрозрачная, потому что на телевизоре стекло не
  читается, а фокус ведёт пульт. Форма взята у таб-бара App Store на iOS 26 — плавающая капсула с
  вкладками плюс ОТДЕЛЬНАЯ круглая кнопка поиска. Это совпало со структурой самого Влада: в
  `TopNav.kt` три вкладки идут группой, а «Поиск» стоит отдельным элементом после отступа.

  Поведение повторяет Apple, а не придумано:

  1. **Скользящая подсветка.** Активная вкладка подсвечивается капсулой, которая ПЕРЕЕЗЖАЕТ между
     вкладками, а не возникает заново на новом месте. Движение — только через `transform`, кадр
     считается на GPU без пересчёта раскладки.
  2. **Пружина без перелёта** (`overshootClamping`). Подсветка обязана остановиться на вкладке;
     качание мимо цели и возврат читаются как неточность.
  3. **Перетаскивание пальцем.** Жест `Pan` соревнуется с `Tap`. Во время скраба подсветка идёт за
     пальцем ОДИН В ОДИН, без пружины (с пружиной жест перестаёт ощущаться прямым), иконки
     разгораются по мере приближения, на каждой границе щёлкает `Haptics.selectionAsync()`.
     Экран переключается ТОЛЬКО при отпускании — иначе протаскивание через три вкладки означало бы
     три загрузки ленты подряд.
  4. **Тап остаётся «прощающим».** `Pan` включается лишь после смещения в 8px (`activeOffsetX`),
     поэтому обычное нажатие не превращается в скраб от дрожания пальца.

  Ровность геометрии держится на одном числе `INSET = 6` (отступ подсветки от краёв со всех сторон)
  и на том, что каждая вкладка занимает ровно `1/3` капсулы. Подписи — в одну строку с
  `allowFontScaling={false}`: крупный системный шрифт иначе ломает сетку, из-за чего панель и
  выглядела рваной.

  Материал выбирается в рантайме: `isLiquidGlassAvailable()` → `GlassView` (настоящий
  `UIVisualEffectView`, только iOS 26+), иначе `BlurView`. Панель `position: 'absolute'` поверх
  содержимого — стеклу нужно, чтобы под ним что-то проплывало; ленты отступают снизу на
  `TAB_BAR_OVERLAP`. Светлая кромка в 1px обязательна: без неё панель читается как дырка в экране.

  Стандартный `Tabs` для этого не годится — панель отрисовывается целиком своя через `tabBar={...}`,
  а всё приложение обёрнуто в `GestureHandlerRootView` (без неё жесты не работают).

  **Отступление от Влада, сделанное осознанно:** в `TopNav.kt` написано «No capsule: the focus cue is
  motion and brightness» — подсветки-капсулы у него нет намеренно. На телевизоре это правильно: там
  фокус и так виден по росту элемента. На телефоне пальцем нужен видимый «где я сейчас», и Apple
  решает это именно капсулой, поэтому здесь она есть.


### Правила Liquid Glass, которым подчинён этот проект

Источник — заметка владельца по дизайну мелочей. Три правила уже были нарушены и исправлены, их
стоит держать в голове при любой правке:

1. **Два слоя, и только два.** Контентный слой (лента, постеры, текст) — плоский и непрозрачный.
   Стеклянный слой — ТОЛЬКО навигация: панель вкладок, тулбары, шторки. Контент никогда не подаётся
   через стекло: материал существует, чтобы отделить хром от читаемого, а не украшать читаемое.
2. **Стекло не ставится на стекло.** Стеклянный слой в системе один; элемент внутри стеклянной
   панели не должен быть отдельной стеклянной поверхностью.
3. **Тонирование только смысловое.** `tintColor` у панели допустим для значения (деструктивное
   действие, активный звонок), а не для фирменного цвета. Здесь этим уже ошиблись: панель вкладок
   тонировалась пергаментным `#CCCC99` — убрано, система подбирает подсветку сама и лучше.
4. **Концентричность** (`src/theme/radii.ts`). Радиус вложенного элемента ВЫЧИСЛЯЕТСЯ: внешний
   радиус минус отступ. Отсчёт от радиуса экрана устройства. Карточка героя отступает на 16 →
   её скругление `SCREEN_RADIUS − 16`, а не подобранное на глаз (было 22 — «спорило» с формой
   экрана). Не ставить радиусы числом, использовать `concentric()`.
5. **Толщина стекла — вычисляемое свойство.** Чем крупнее панель, тем «толще» материал: глубже
   тень, заметнее линзирование. Мелкая кнопка почти не искажает фон, крупная шторка — заметно.
6. **Доступность обязательна** (`src/theme/a11y.ts`). Reduce Motion гасит морфинг до затухания,
   Reduce Transparency заменяет просвечивание заливкой. Для нативной панели это делает iOS; всё,
   что рисуем сами, обязано слушать те же настройки — иначе приложение окажется единственным
   местом в системе, которое их игнорирует. Контраст текста к фону под стеклом — не ниже 4.5:1;
   если содержимое пёстрое, затемняющий слой добавляем сами (этим заняты виньетки на обложках).
7. **Кривая морфинга — отдельная** (`MorphSpring` в `theme/motion.ts`). У Apple слияние и раскрытие
   стеклянных форм идут пружиной с лёгким перелётом, 0,35–0,4 с. Это не то же самое, что отклик
   интерфейса, поэтому она НЕ входит в три длительности Влада — там кривая без перелёта.

Исключение, зафиксированное сознательно: **плашка рейтинга остаётся с острыми углами**. Правила выше
описывают стеклянный слой навигации, а плашка живёт в контентном слое, на который они не
распространяются; там действует прямое требование Влада — «без скругления углов».


### Раскрытие карточки: техника и почему именно такая

Разобрано покадрово по записи App Store (30 к/с). Две вещи, на которых легко ошибиться:

**Содержимое не растягивается.** Пропорции карточки в ленте и экрана разные. Если масштабировать
страницу по двум осям (scaleX/scaleY), текст плющит всю анимацию — на записи Apple этого нет.
Работает ОКНО: рамка едет от прямоугольника карточки к прямоугольнику экрана (меняются положение,
размер, скругление), а страница внутри лежит в полный размер экрана и масштабируется РАВНОМЕРНО,
одним числом, привязанная к левому верхнему углу. Тогда ширина страницы всегда совпадает с шириной
рамки, а по высоте видно ровно столько, сколько влезло — в начале верх обложки, дальше остальное.
Побочная выгода: скругление задаётся рамке в настоящих точках и не искажается масштабом.

**Фон размывается, а не темнеет.** На кадрах домашний экран за растущей карточкой явно
расфокусирован. Одно затемнение даёт плоскую чёрную подложку и съедает половину впечатления.

**Скорость.** По кадрам рост занимает ~7 кадров при 30 к/с, то есть около 230 мс. Здесь 280 мс на
открытие и 240 на закрытие (закрытие быстрее: решение уже принято, ждать нечего). Не ставить сюда
400 мс с мягкой пружиной — так было, и это вдвое медленнее оригинала, отсюда ощущение вязкости.

### Чего в передаче не оказалось

**Надпись «ЛЮМЬЕР» получена от Влада напрямую** и лежит в `assets/brand/` — обычная и новогодняя,
подмена по датам работает (см. `src/components/Logo.tsx`). Остальное отсеклось из-за правила в
`.gitignore` — это стоит починить у Влада. Там есть строка
`*.png` с комментарием «скриншоты с отладки, их набралась сотня», но правило безусловное и выносит
ВСЕ png в проекте, включая `app/src/main/res/drawable-nodpi/`. Именно там лежат `logo_mark_img`,
`brand_wordmark`, `brand_wordmark_ny` (версия с шапкой Деда Мороза, показывается с 10 декабря по
8 января) и `brand_full`, на которые ссылается `Logo.kt`. В переданной папке эта директория пустая.

То же самое случится и с git-репозиторием, если Влад выполнит `git init && git add .`, как советует
его же `HANDOVER.md` — логотипы молча не попадут в коммит. Правило стоит сузить, например до
`/*.png` (только корень проекта, где скриншоты и лежат).

Ещё не хватает: `logo_mark_img` (металлический компактный знак) и `brand_full` (полный логотип для
пустых экранов и онбординга) — оба png из `app/src/main/res/drawable-nodpi/`. Класть в
`assets/brand/`. Пока вместо `logo_mark_img` используется векторный знак из `logo_mark.xml` — он
дошёл только потому, что он `.xml`, а не `.png`.

**Расхождение комментария и кода в оригинале.** В `Logo.kt` написано, что новогодняя надпись
показывается «с 10 декабря по 8 января», но сама `isNewYearSeason()` в `Occasions.kt` считает
`v >= 1212 || v <= 107`, то есть **с 12 декабря по 7 января**. Здесь повторено поведение КОДА.
Это одно окно на весь праздник — та же проверка включает карточку «Итоги года» и новогодний
марафон; второй календарь заводить не надо.

Ещё не перенесено из оформления: анимация числа рейтинга на экране деталей (число не просто
появляется, а ЗАЛИВАЕТСЯ цветом снизу вверх по мере досчёта, выше 8.0 — конфетти, выше 8.7 —
прожекторы вместо конфетти), значки наград/«свежести» Rotten Tomatoes (`TomatoGlyph`), бейдж
возрастного рейтинга.

## Чего пока нет (следующие этапы)

- **HDRezka и плеер** — самая объёмная часть: логин, обход anti-bot защиты Anubis (SHA-256
  proof-of-work, `AnubisSolver.kt` — портируется почти дословно), деобфускация ссылок
  (`HdRezkaTrash.kt`), выбор озвучки и качества (`HdRezkaModels.kt` с его порядком предпочтения
  озвучек), субтитры. Плеер — на `expo-video`, он умеет HLS и mp4 из коробки.
- **История просмотра, «Продолжить просмотр», «Моё»** — `data/watch/*`.
- **Кинофесты** (`Marathons.kt`, 134 КБ контента) и **календарные ряды** (`Occasions.kt`, 25 КБ:
  праздники, «в этот день», дни рождения, годовщины). В ленте пока нет ни праздничных вариантов
  ряда настроения, ни календарных рядов.
- **Торренты (TorrServer)** — на iOS требуют принципиально другого движка; за скобками мобильной
  версии.
